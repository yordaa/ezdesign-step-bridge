# JSON Reader Capability

## MODIFIED Requirements

### Requirement: Command-Line Tool

The system SHALL provide a command-line tool `ezd2step` for converting EZDesign JSON files to STEP format.

#### Scenario: Convert JSON to STEP file
- **GIVEN** a valid JSON file and output STEP filename
- **WHEN** `ezd2step input.ezd output.step` is executed
- **THEN** the JSON file is read and parsed
- **AND** topology/geometry is converted to OCCT shapes
- **AND** shapes are exported to STEP format
- **AND** the STEP file is created at the specified path
- **AND** the generated STEP file is verified using OCCT's `STEPControl_Reader`
- **AND** if verification fails, detailed error messages identify the problematic entities or structure
- **AND** the command exits with exit code 0 on success

#### Scenario: Verify generated STEP file
- **GIVEN** a STEP file generated by `ezd2step`
- **WHEN** OCCT's `STEPControl_Reader::ReadFile()` is called on the file
- **THEN** the file is successfully parsed (status = `IFSelect_RetDone`)
- **AND** check messages from `PrintCheckLoad()` are reported
- **AND** if parsing fails, detailed error messages identify:
  - Which entities have errors
  - What type of error occurred (syntax, structure, geometry)
  - Line numbers or entity numbers where errors occur
- **AND** the shape can be transferred and analyzed (faces, edges, vertices counted)

#### Scenario: Handle file errors
- **GIVEN** a non-existent input file
- **WHEN** `ezd2step` is executed
- **THEN** an error message is displayed on stderr
- **AND** the program exits with non-zero exit code (e.g., 2 for file I/O error)

#### Scenario: Report conversion progress
- **GIVEN** a large JSON file being converted
- **WHEN** `ezd2step` processes the file
- **THEN** progress messages are displayed on stdout (e.g., "Reading JSON...", "Converting...", "Writing STEP...")
- **AND** error messages are displayed on stderr with context (which element failed)

#### Scenario: Exit code contract
- **GIVEN** `ezd2step` is executed
- **WHEN** conversion succeeds
- **THEN** exit code is 0
- **WHEN** conversion fails due to invalid arguments
- **THEN** exit code is 1
- **WHEN** conversion fails due to file I/O error
- **THEN** exit code is 2
- **WHEN** conversion fails due to JSON parsing error
- **THEN** exit code is 3
- **WHEN** conversion fails due to geometry conversion error
- **THEN** exit code is 4
- **WHEN** conversion fails due to STEP export error
- **THEN** exit code is 5

## ADDED Requirements

### Requirement: C API Entrypoint

The system SHALL provide a C API entrypoint (`ezd_to_step`) in shared library form for programmatic integration.

#### Scenario: C API function signature
- **GIVEN** C API is implemented
- **WHEN** `ezd_to_step` function is called
- **THEN** the function accepts `input_path` (const char*), `output_path` (const char*), and optional `options` (struct pointer)
- **AND** the function returns integer exit code (0 = success, non-zero = failure)
- **AND** exit codes match CLI exit codes (0, 1, 2, 3, 4, 5)

#### Scenario: C API options structure
- **GIVEN** C API is implemented
- **WHEN** options structure is defined
- **THEN** structure includes `verbose` field (int: 0 = quiet, 1 = progress, 2 = debug)
- **AND** structure includes optional `log_file` field (const char*, NULL = no log file)
- **AND** structure can be NULL (use default options)

#### Scenario: C API shared library
- **GIVEN** C API is implemented
- **WHEN** shared library is built
- **THEN** library is built as `.dylib` on macOS or `.dll` on Windows
- **AND** library exports `ezd_to_step` function symbol
- **AND** library can be linked dynamically by downstream applications

#### Scenario: C API usage
- **GIVEN** C API shared library and header file
- **WHEN** downstream application includes header and links library
- **THEN** application can call `ezd_to_step` function
- **AND** function converts `.ezd` file to `.step` file
- **AND** function returns appropriate exit code
- **AND** function respects options (verbose level, log file)

#### Scenario: C API error handling
- **GIVEN** C API is called with invalid arguments
- **WHEN** `ezd_to_step` is called with NULL input_path or output_path
- **THEN** function returns exit code 1 (invalid arguments)
- **AND** no file operations are performed
